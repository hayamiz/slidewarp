# 公開用サンプル匿名化ツール 設計書

- 日付: 2026-08-07
- 対象: `input-samples/` の実写真から、公開可能な匿名化サンプルを生成する運用ツール

## 目的

`input-samples/`（git 非追跡）にある学会撮影のスライド写真から、**難ケース代表を数枚（6枚前後）厳選**し、
以下を施した**公開用サンプル**を作って git 追跡する。

1. 顔（人物マスク上部から推定）をモザイク化（プライバシー処理）
2. スライド内部をモザイク化・**四辺のエッジは無処理**（著作権処理＋検出テスト性の維持）
3. EXIF/メタデータの除去（個人情報処理）

公開物はスライド検出アルゴリズムの**回帰テスト資産としての価値を保つ**ことを絶対条件とする
（＝匿名化しても Rust 本体の検出結果が元と変わらないこと）。

法的な公開可否（肖像権・著作権）の最終判断はユーザー（研究者）が行う。ツールは
「機械的な匿名化＋検証補助」までを担う。

## スコープ / 非スコープ

- **スコープ**: 厳選 6 枚前後の匿名化、自動回帰チェック、目視レビュー支援（review.html）、
  合格分のみ昇格するワークフロー。
- **非スコープ**: slidewarp 本体 CLI への機能追加、全 35 枚の一括匿名化、法的判断の代行。

## ディレクトリ構成と git 追跡

```
input-samples/        # 非追跡（現状のまま）。匿名化の入力＝元写真の保管場所
samples/              # ★新設・git追跡。公開用の匿名化済みサンプル
  ├── README.md       # 各画像が「何をテストするか」を説明
  ├── <img1>.jpg ...  # 匿名化済み6枚前後
  └── _staging/       # 非追跡。レビュー待ちの生成物置き場＋review.html
python/scripts/anonymize_samples.py   # ★新設。生成＋検証＋review.html＋昇格
python/samples.toml                   # ★新設。厳選リストと手動オーバーライド設定
```

- 元写真を別途 `orig/` に退避する必要はない。`input-samples/`（既に非追跡）がそのまま元データ置き場。
- `samples/` は現 `.gitignore` の除外対象外なので追跡できる。
- `.gitignore` に `samples/_staging/` を追記して、レビュー前の生成物の誤コミットを防ぐ。

## 匿名化パイプライン（1 枚あたり）

入力: `input-samples/<name>` → 出力: `samples/_staging/<name>`。以下を元画像座標で行う。

### ① スライド内部のモザイク（辺は無処理）

- slide quad は **Rust 本体（正）の `--dump-geom` 出力を parse** して取得する
  （Python 版 detect ではなく、正の検出結果に合わせる）。
- quad を各辺**内側に安全マージン（既定 `mosaic_inset = 0.06`）だけ縮めた内側 quad** を作り、
  その内側多角形（台形に追従）だけをモザイク化する。真の四辺・エッジ帯はシャープなまま残す。
- モザイク = **pixelate**（領域を小ブロックに縮小 → 最近傍拡大）。ブロック粒度は
  「本文テキストが判読不能」になる大きさ（既定 `mosaic_block = 16` = 領域短辺の約 1/16 目安、パラメータ化）。

### ② 顔のモザイク（人物マスク上部から推定）

- Python 版 `slidewarp.ml.PersonSegmenter`（DeepLabV3 person、`[ml]` extra）で人物マスクを取得。
- 連結成分ごとに bbox の**上部バンド（既定 `face_band = 0.22`）**を顔領域とみなしモザイク化。
- 既知の弱点（融合塊・後ろ向き・小さい顔の取りこぼし）は目視ゲートで担保し、
  漏れは `samples.toml` の `faces` 手動矩形で塞ぐ。

### ③ EXIF・メタデータ除去

- 出力時に EXIF/GPS/端末情報を含む全メタデータを落としてクリーンに書き出す。

### 処理順

- ①スライド内部と②顔で元画像座標のマスクを独立に作り、**2 段で適用**する（①→②の順）。

> **実装で確定した重要な方針転換（2026-08-07）**: 当初「スライド内部もモザイク(pixelate)」で
> 設計したが、実走検証で**内部モザイクの軸平行なブロック境界エッジを Rust の Hough が真の
> スライド辺と誤検出し、検出 quad が大きくずれる（高解像度で最大 736px・aspect 反転）**ことが
> 判明した。このため**①スライド内部は「軽いガウシアンぼかし」（`apply_blur`、グリッド線を
> 作らない）に変更**し、②顔のみモザイク(pixelate)を維持する（誤セグメントの広い顔帯は幅制限）。
> ぼかし σ は軽め固定（既定 15px）で検出忠実度を優先する。詳細は
> [`plans/2026-08-07-anonymize-samples.md`](../plans/2026-08-07-anonymize-samples.md) と
> `samples/README.md` を参照。

## 検証ゲート（自動＋目視の二段）

「staging に生成 → 自動チェック → 目視 → 合格分だけ `samples/` へ昇格」の一方向フロー。

### 自動チェック（Rust 本体＝正で回帰ゼロを機械判定）

元写真と staging 版それぞれに slidewarp を走らせ比較する。

| 項目 | 取得元 | 合格条件（既定） |
|---|---|---|
| 検出 quad 4 隅 | `--dump-geom` | 各隅のズレが画像長辺の **1% 未満** |
| method（contour/hough/minrect） | `--dump-geom` | 完全一致 |
| アスペクト判定（4:3/16:9） | `--dump-geom` | 完全一致 |
| confidence | 通常実行のログ | 差 **0.03 未満** |

1 項目でも外れたら **FAIL**（モザイクが辺に掛かって検出を動かした兆候）。

### 目視チェック

- staging に **`review.html`（コンタクトシート）** を生成。各画像を「元 | 匿名化版」横並び＋
  自動チェックの PASS/FAIL・各差分値を注記。
- 人が 3 点を確認: (a) 顔が消えているか（融合塊の取りこぼしがないか）、
  (b) スライド本文が判読不能か（著作権）、(c) 辺にモザイクが掛かっていないか。

### 昇格と失敗時のフォールバック

- `--promote` は**自動チェック PASS の画像だけ**を `samples/` へコピーする（FAIL は昇格対象外）。
  目視 OK は機械フラグでは持たず、「`review.html` を確認したうえで人が `--promote` を実行する」
  という運用で担保する（＝人手レビューが昇格の実質的ゲート）。
- FAIL / 目視 NG は `samples.toml` に**手動オーバーライド**（slide quad の手座標、顔の手動矩形）を
  書いて再生成 → 再チェック。難ケース（`19.55.25` 等）はここで手当てする。

## ツール構成

人物セグメンテーションが Python 専用のため、匿名化ツールは Python 側の単体スクリプトにする
（slidewarp 本体 CLI には組み込まない）。

### `samples.toml`（設定の実体）

```toml
mosaic_inset = 0.06        # スライド内側マージン（既定）
mosaic_block = 16          # pixelate ブロック粒度（既定）
face_band = 0.22           # 人物マスク上部の顔バンド比

[[image]]
src = "2026-06-23 08.44.43.jpg"
note = "遠景・強い台形歪み・下辺に観客の頭（下辺オクルージョン）"
# quad = [[x,y],...]        # 任意: 自動検出が不良なら手座標で上書き
# faces = [[x,y,w,h],...]   # 任意: 顔取りこぼしの手動追加

[[image]]
src = "2026-06-24 19.47.29.jpg"
note = "明壁投影・登壇者が前に立つ"
# ...厳選 6 枚分
```

### コマンド（`python/` 内、`uv` 前提。事前に `cargo build --release`）

```bash
uv sync --extra ml                                    # torch 導入（顔検出用）
uv run python scripts/anonymize_samples.py            # 生成→staging + 自動チェック + review.html
# → samples/_staging/review.html を目視確認
uv run python scripts/anonymize_samples.py --promote  # 全PASSかつ承認済みを samples/ へ昇格
```

- `--promote` なし = 生成＋検証まで（staging 止まり）、`--promote` で自動 PASS 分を昇格。
  単一スクリプトにモードをフラグで集約。

## リスクと既知の限界

- **顔取りこぼし（プライバシー漏れ）**: 人物マスク上部からの顔推定の構造的弱点。融合塊・後ろ向き・
  小さい顔・未検出は当たらない。→ 目視ゲート必須、漏れは `faces` 手動矩形で塞ぐ。6 枚厳選で現実的に。
- **著作権の塗り残し**: 自動検出 quad が真のスライドより内側にずれると本文が残る（`19.55.25` 上辺等）。
  → 目視で「本文が全て判読不能か」を確認し、不足は手動 quad 拡張で塞ぐ。最終判断は人。
- **モザイクの不可逆性**: pixelate は低周波を残すため粒度は十分大きく。必要ならモザイク＋軽いぼかし併用。
- **検出回帰と匿名化のトレードオフ**: 内部モザイクが強いと fill/contrast がわずかに動きうる。
  自動チェックの confidence 差 0.03・quad 1% でこれを捉え、超過は FAIL として手当て。
- **法的判断はツール外**: 公開可否の最終判断はユーザーが行う。
